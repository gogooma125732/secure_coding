# SAFER 유지보수 절차

## 목적

기능 변경과 보안 수정이 기존 인증·권한·거래 무결성을 훼손하지 않도록 반복 가능한 유지보수 절차를 정의한다.

## 변경 절차

1. 사용자 오류, 보안 경보 또는 의존성 경고를 접수한다.
2. 요청 ID, 감사 로그와 재현 절차로 영향 범위를 확인한다.
3. 실패를 재현하는 회귀 테스트를 먼저 추가한다.
4. 최소 범위로 코드 또는 신규 DB 마이그레이션을 작성한다.
5. 타입 검사, 린트, 보안 검사와 전체 테스트를 실행한다.
6. 보안 경계 변경 시 OWASP 통제표와 위협 모델을 갱신한다.
7. 검증된 소스만 새 버전으로 배포한다.
8. 배포 후 Worker 오류와 관리자 보안 경보를 확인한다.
9. 문제가 발생하면 직전 저장 버전으로 롤백하고 원인을 기록한다.

## 필수 검증

```bash
npx tsc --noEmit
npm run lint
npm run security:check
npm test
```

웹 경계가 변경되면 ZAP Baseline을 추가하고, Active Scan은 localhost에서만 수행한다.

## 데이터베이스 변경

- 마이그레이션은 새로운 번호로 추가한다.
- 운영 환경에 적용된 SQL은 수정하거나 재사용하지 않는다.
- 권한·잔액·거래 상태 변경은 감사 로그를 남긴다.
- 운영 사용자나 관리자 아이디를 마이그레이션에 하드코딩하지 않는다.
- 파괴적 변경 전 백업·복원 가능 여부와 롤백 방법을 문서화한다.

## 의존성 유지보수

- lockfile 없이 배포하지 않는다.
- High 이상 취약점은 원칙적으로 배포 차단 사항이다.
- Dependabot PR도 전체 테스트를 통과해야 병합한다.
- 무리한 강제 버전 변경보다 공식 보안 릴리스와 호환성을 확인한다.

## 사고 대응

1. 영향받는 기능을 제한하거나 이전 안전 버전으로 롤백한다.
2. 노출 가능성이 있는 secret과 세션을 회전한다.
3. 감사 로그와 요청 ID를 보존한다.
4. 원인과 영향 범위를 분석한다.
5. 수정 및 회귀 테스트 후 재배포한다.
6. 재발 방지 통제와 잔여 위험을 보고서에 기록한다.
